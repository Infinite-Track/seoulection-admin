# 기능성 조회 작업 큐

외부 조회는 화면 요청이 아니라 PostgreSQL 작업 테이블과 단일 워커에서 실행한다.
API 서버 V25(작업 테이블), V26(설정 테이블), V27(기본값 변경) 마이그레이션을 먼저 적용한 뒤 어드민을 배포해야 한다.

- 자동 등록: INGREDIENTS_ADDED 상태이며 한글 이름이 있는 제품. 기본 10분마다 누락 작업 등록.
- 자동 등록 순서: 등록일(created_at) 오래된 순, 같은 날짜는 제품 ID 오름차순. 등록일이 없는 기존 문서는 ID 오름차순으로 먼저 조회한다.
- 워커 처리 순서: 대기열 등록 시각(queued_at) 오래된 순. 기존 대기 작업의 순서는 바꾸지 않는다.
- 기능성 목록: 기본 등록일 오래된 순, 최신순 버튼으로 전환 가능. 검색·조회 상태 필터·페이지 이동 시 선택 정렬을 유지한다.
- 화면 진입: 저장된 후보 및 작업 상태 조회만 수행. 외부 호출 없음.
- 수동 조회: 이름 저장/재조회 버튼은 큐 등록만 수행.
- 동시 실행: PostgreSQL 세션 advisory lock으로 여러 인스턴스에서도 전역 1개.
- 대기열: 기본 최대 20개(대기+실행 합계), 제품별 중복 등록 차단.
- V27은 기존 기본값 5분/100개만 10분/20개로 변경하며 관리자 맞춤 설정은 유지한다.
- 처리 간격: 작업 종료 후 기본 5초. 제품 안의 기존 안전나라 호출은 순차 실행.
- 실패: 자동 무한 재시도 없음. 수동 재조회는 종료 후 1분 간격 제한.
- 재시작: 대기 작업 유지. 중단된 실행 작업은 FAILED로 전환하고 관리자 재시도 필요.
- 입력 변경: 이름/브랜드/카테고리 fingerprint가 변경되면 재등록.
- 관리자 확정 또는 입력 변경 시 오래된 결과 저장을 검사하여 막는다.
- 최종 제품 기능성/상태는 관리자의 저장 요청에서만 변경한다.
- 화면은 5초 간격으로 상태와 앞선 작업 수를 확인한다. 완료 시 결과 보기 버튼을 표시하며
  작성 중인 수동 검수 폼을 보호하기 위해 자동 새로고침하지 않는다.

기존 Mongo 판정 결과가 있으나 작업 기록이 없는 제품은 최초 스캔 시 현재 입력을 기준으로
완료 기록을 만든다. 기존 결과 생성 당시와 입력이 달라졌다면 최초에는 수동 재조회가 필요하다.

설정 탭: 제품 관리 → 기능성 확인 → 설정 (`/admin/products?stage=functional-review&tab=settings`).
자동 등록 토글·주기·한도를 조정한 뒤 설정 저장을 눌러 적용한다. 기존 `/admin/functional-screening-settings` 주소는 설정 탭으로 이동한다.
자동 등록 활성화, 등록 주기(1~1440분), 대기열 한도(1~1000개)를 DB에 저장한다.
재시작 없이 반영되며, 워커와 별개로 15초마다 설정 테이블 한 행에서 등록 주기 도래를 검사한다.
등록 주기는 DB의 last_scan_at을 기준으로 관리하므로 다중 인스턴스에서도 같은 주기의 중복 스캔을 막는다.
설정 저장은 기준 시각을 초기화해 활성화되어 있으면 다음 확인 주기에 첫 스캔을 시작한다.
자동 등록을 꺼도 기존 작업과 수동 등록은 유지한다. 한도를 낮춰도 기존 작업은 삭제하지 않는다.
서버 전체 자동 조회 활성화는 기존 enabled 설정을 따른다(꺼져 있으면 페이지에서 경고).
워커 간격/초기 지연은 `admin.functional-screening.queue.worker-delay-ms`, `initial-delay-ms`로 설정한다.
FUNCTIONAL_SCREENING_APPLY는 삭제되어 어떤 값으로 설정해도 자동 확정 경로가 없다.

주의: PostgreSQL 작업 상태와 Mongo 결과 저장은 분산 트랜잭션이 아니다.
검사 직후 발생하는 동시 수정까지 완전히 차단하려면 Mongo의 버전 기반 조건부 결과 저장이 필요하다.
현재 구조에서도 워커는 최종 제품 기능성과 상태를 수정하지 않는다.
